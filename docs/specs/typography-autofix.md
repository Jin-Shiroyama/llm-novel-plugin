# 表記の点検と自動整形

## 背景

49988ef で整形を追加し、583946c・756f040 で URL・罫線・数値範囲などを保護した。点検と整形を別実装にしていたため、保護判定が食い違い、傍点の外へ文字を追加する問題が残った。

## 処理の正本

`text-analysis.ts` が行種別、表示文字と元の位置の対応、ルビ・傍点の範囲、URL の範囲を解析する。表記点検と文章点検はこの行種別を共有する。

`checkTypography` が規則の診断と任意の `fix` を同時に生成する。`fixTypography` はその修正案だけを適用する。重なった編集は次の解析で評価し、修正案が無くなるまで処理する。危険な編集には修正案を付けず、エラーが残っても推測で書き換えない。

約物の役割は `punctuation.ts` で正規化前から判定する。`...`・`‥`・`・・` 以上などの三点リーダ、`—`・`─`・`–` などのダッシュを、空白・字下げ・置換で共用する。数値範囲・罫線の例外は維持する。`「！...」`・`「！—」` に空白を仮挿入しない。

修正件数は実際に適用した規則ごとの編集数で、行数・文字数ではない。無変更の編集を数えず、処理前後が同じ行は0件。複数パスをまたぐ編集合成や相殺追跡はしない。

行ごとに最大16パス（コア関数の `maxPasses` で変更可）と同一文字列の再出現を検査する。未収束時は `unconvergedLines`（1始まり）と原文全体を返し、修正件数0・差分なしにする。保存ツールは保存を中止し、点検ツールはそのファイルを上書きせず原文を点検する。他のファイルは独立して処理する。通常終了時も `unconvergedLines` は空配列として返す。

修正位置は元の行のコードポイント単位・0始まり・終端を含まない。診断の表示位置は従来どおり1始まり。

## 行種別と規則

| 行の種類 | 字下げ | 約物・数字 | 文章点検 |
|---|---|---|---|
| 空行・見出し | 保持 | 保持 | 対象外 |
| 区切り・罫線枠・飾り見出し | 保持 | 保持 | 対象外 |
| 会話 | 字下げを除去 | 点検し、安全なものだけ修正 | 対象外 |
| 地の文 | fullwidth / none に従う | 点検し、安全なものだけ修正 | 対象 |
| ステータス・通知・コメント・ラベル行 | 全角・半角空白・タブを保持 | 点検し、安全なものだけ修正 | 対象外 |

三点リーダ・ダッシュで始まる行は字下げしない。意図的な全角2字以上の字下げは fullwidth 設定では警告のみ。none 設定では全角字下げの警告にも除去の修正案を付ける。診断の重大度と修正可能性は別の属性。

表示行は上記の字下げ規則と「段落頭に半角スペースやタブを使わない」規則の例外とする。`（心の声）`・`理由：彼は寝坊した。` の先頭空白の誤りを見逃す場合も、レイアウト保持を優先する。

行分類は空行 → 行頭 `#` の見出し → 罫線・区切り → 会話／三点リーダ・ダッシュ始まり → 表示行 → 地の文の順。`　・・・と呟いた。` は初回から字下げ除去、`　・HP：100` は保持する。`　#拡散希望` は見出しにしない。

括弧崩れ、長音符「ーー」、用語集、日本語と英数字の間の空白は自動修正しない。壊れたルビの行では、元の先頭空白を安全に処理できる場合を除き編集しない。

## 保護範囲

- URL・ルビの読み・記法の区切りは変更しない。
- 傍点本文内の置換は同じ傍点内に収める。対象を空にする削除はしない。
- ルビの親文字は文字数を保つ置換のみ許す。親文字の追加・削除や記法をまたぐ編集は手動。
- 数字間の単独 en-dash（第1–3層など）は範囲表記として保持する。
- 裸の URL に日本語が続く場合、パスか本文かを決められないため候補範囲を保護し、境界が曖昧と通知する。空白か `<...>` で区切ると範囲が明示される。明示範囲の後ろにある本文は通常どおり点検・整形する。

URL の範囲解析は `urls.ts` を共用する。裸の URL は全角括弧 `【】＜＞（）「」『』《》〈〉〔〕［］｛｝` と `、。！？…―` で常に終了し、直前の開き括弧には依存しない。半角 `()`・`[]` は URL 内で開いた分だけ対応する閉じを含める。`(参照: https://example.com/Foo_(bar))` の外側の `)` は保護しない。

`<...>` は内部が http(s) URL または裸ドメイン形式を満たす場合だけ明示範囲とする。`<SYSTEM>`・`<Lv.5>` は対象外。明示 URL はルビ解析でも独立した文字列として保持し、`convertRuby` の全形式（青空文庫を含む）で内部の《》を変換しない。

傍点の内側に置いた明示 URL（`《《<https://example.com/a>》》`）は未対応。明示 URL の先行保護で外側の記法が分断されるため、記法エラーとして通知し、自動整形しない。URL は傍点の外に置く。

裸ドメインの検出には `Dr.Smith/佐藤だよ!` のような略語の誤検出が残る。候補範囲の保護を優先し、「URL 候補の境界が曖昧」と通知する。辞書による推測は行わない。

## 保存と互換性

保存時の `autoFix` は既定 true（`constants.ts` の `DEFAULT_AUTO_FIX`）。整形せずにそのまま保存したい場合は `autoFix: false` を明示する。既存ファイルの一括整形は `novel_check(fix: true)` を使う。

実行時とツール引数説明は `constants.ts` の `DEFAULT_AUTO_FIX` を参照する。スキル・案内・執筆プロンプトは規則と有効化条件を分け、既定値を個別に重複記載しない。

変更前の原稿を退避する。同じ保存結果なら旧稿・整形前の控えを増やさず、本文ファイルも再書き込みしない。差分表示は最初の変更位置を中心に切り出す。整形関数は改行形式を含め、変更不要な文字列を保持する。

## 受け入れ条件

| 入力 | 期待する整形後 |
|---|---|
| `「《《…》》」` | `「《《……》》」` |
| `「《《...》》」` | `「《《……》》」` |
| `「｜…《てん》」` | 無変更、三点リーダの診断は残す |
| `「《《！》》続き」` | `「《《！》》　続き」` |
| `https://example.com/検索?q=1` | URL 範囲を保持、境界の警告 |
| `「サイトは<example.com/top>だよ。」` | `「サイトは<example.com/top>だよ」` |
| `第1–3層`、枠・飾り見出し | 保持（地の文の字下げは設定に従う） |

全スキル作例は表記エラー0件・文章検出0件・文字列無変更。さらに整形の冪等性、記法の対象範囲、修正可能な診断が残らないこと、再保存時のバックアップ数を検証する。点検エラー0件だけでは、記法の保持の保証に代えない。
